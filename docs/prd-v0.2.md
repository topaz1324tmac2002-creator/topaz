## 0. 한 장 요약

**한 줄 정의**
> 브라우저(아이패드·PC)에서 **반지 하나를 5분 만에 디자인하고**, 금속 중량과 출력 가능 여부를 즉시 확인해 **바로 3D 프린팅·주물로 넘기고, 그 과정을 쇼츠/릴스용 15초 영상으로 뽑아내는** 경량 주얼리 디자인 웹앱.

**핵심 6기능 (MVP)**
1. **파라메트릭 반지 생성기** — KS/US 호수, 폭·두께, 단면 프로파일(돔·플랫·베벨 등) + 컴포트 핏
2. **스톤 & 세팅** — 프롱/베젤 세팅 프리셋, 스톤 크기·개수·배치
3. **자유 조형(스컬프팅)** — 밀기/당기기/스무스 브러시로 실제 메쉬 정점 변형 *(D2 확정으로 MVP 포함)*
4. **각인 & 실시간 재질 렌더링** — 금·은·로즈골드 6종 + 보석, 360도 턴테이블(9:16 영상 저장)
5. **3D 프린팅 출력 준비** — 예상 금속 중량(g) 계산, Watertight(수밀) 검증, STL 원클릭 내보내기
6. **(공통)** 디자인 자동 저장·불러오기(로그인 없이 기기 내 저장)

**왜 만드는가 (3문장)**
라이노(Rhino)는 주얼리 업계 표준이지만 입문자가 "반지 하나"를 완성하려면 수 주가 걸리고, 라이선스·장비·렌더링 도구가 따로 놀아 수업 시간의 절반이 준비 작업에 쓰입니다. 이 앱은 **반지라는 하나의 오브젝트에 기능을 전부 몰아넣어**, 수업 첫 시간에 학생 전원이 STL 파일까지 도달하게 만듭니다. 동시에 결과물이 곧 콘텐츠가 되도록(턴테이블 영상) 설계해, 교수님의 유튜브 쇼츠·인스타 릴스 브랜드와 자연스럽게 연결합니다.

**일정 제안**
8주 · 4스프린트(2주 단위) → 9주차 수업 파일럿. 개발 인력 1명(또는 AI 코딩 에이전트 병행) 기준이며, 3장의 P0 기능만으로도 수업 사용은 가능합니다.

**먼저 결정해 주실 것 (2가지, 6.2에 상세)** → **✅ 2026-11-14 교수님 확정**
1. **첫 타겟 환경** → **① 아이패드(터치) 우선, PC 웹은 같은 코드로 자동 지원**
2. **MVP 반지 범위** → **② "만들 수 있는 건 다" — 표준 밴드 + 스톤 세팅 + 각인 + 자유 조형 + 중량/STL까지**
   (초안의 추천은 ①이었으나, 교수님 판단으로 조형까지 포함. 그에 맞춰 1차 프로토타입에 스컬프팅을 넣었습니다 — 7장)

### 1.1 제품 정의

| 구분 | 내용 |
|---|---|

### 1.2 문제 정의 (Pain points)

교수님 수업 현장에서 반복적으로 발생하는 마찰을 기준으로 정리했습니다.

| # | 문제 | 현재 방식 | 이 앱이 해결하는 방식 |
|---|---|---|---|
| P1 | 학습 곡선 | 라이노 NURBS 개념·단축키 학습에 2~3주 | 파라미터 슬라이더 5개로 첫 결과물 5분 |
| P2 | 라이선스·장비 | 라이노(교육용)·KeyShot·프린터 슬라이서 각각 필요 | 브라우저만 있으면 전 과정. 무료 티어로 학생 배포 가능 |
| P3 | 수업 시간 낭비 | 모델링→렌더링→익스포트→슬라이서 점검을 각각 수행 | 검증·중량·STL이 한 버튼 |
| P4 | 출력 실패 | Watertight 아님·벽 두께 부족으로 프린트 실패, 재수업 | 저장 전 자동 검증 + 문제 위치 표시 |
| P5 | 중량·원가 감각 없음 | 출력 후 주물 의뢰하고 나서야 중량/원가 확인 | 디자인 중 실시간 중량(g) 표시 |
| P6 | 결과물이 콘텐츠가 안 됨 | 렌더 이미지 캡처, 별도 편집 | 9:16 턴테이블 영상 원클릭 저장 |
| P7 | 브랜드 자산 없음 | 개인 작업물로만 남음 | 모든 결과물에 브랜드 워터마크·갤러리(V2) |

## 2. 타겟 사용자 및 활용 시나리오

### 2.1 페르소나

**U1 — 김영훈 교수 (제품 오너 / 수업 진행자)**
- 대학 금속공예·주얼리 디자인 전공 교수. 3D 모델링·렌더링·3D 프린팅을 수업에 연결.
- 니즈: 수업 중 시연이 끊기지 않을 것, 학생이 집에서도 이어서 할 것, 결과물이 자기 브랜드(쇼츠/릴스)로 이어질 것.
- 제약: 개발에 쓸 시간이 학기 중에는 주 2~3시간. 코드를 직접 쓰지는 않음 → **AI 에이전트로 유지보수 가능한 단순한 구조**가 필수.

**U2 — 수강생 (20명 내외, 2~4학년)**
- 3D 툴 경험 편차 큼. 절반은 태블릿만, 절반은 노트북. 라이노는 커녕 블렌더도 처음인 학생 다수.
- 니즈: 설치 없이 바로, 실패해도 되돌리기 쉬울 것, 과제 제출 형식이 명확할 것.
- 제약: 학교 와이파이, 개인 기기 성능 편차, 아이패드 Safari.

**U3 — 일반 사용자 / 잠재 고객 (V1.5 이후)**
- 커플링·기념 반지를 직접 만들어보고 싶은 사람, 교수님 채널을 보고 유입된 시청자.
- 니즈: 회원가입 없이 체험, 결과물을 이미지로 공유, "실물로 만들기"로 이어지는 경로.

### 2.2 해결하려는 일 (Jobs to be done)

- "수업 자료를 준비할 때, 학생들이 5분 만에 손에 잡히는 결과물을 갖게 하고 싶다."
- "과제를 낼 때, 학생이 만든 게 실제로 출력 가능한지 내가 일일이 검사하지 않아도 되면 좋겠다."
- "내 작업 과정을 콘텐츠로 쓰고 싶은데, 촬영·편집에 쓰는 시간을 줄이고 싶다."
- "학생이 '내 반지가 은으로 하면 몇 g, 얼마인지'를 스스로 감각적으로 알면 좋겠다."

### 2.3 핵심 시나리오

**S1. 수업 시연 (90분, 실습실)**
1. (5분) 교수님이 링크로 접속 → 템플릿 "수업 1주차_기본 밴드" 클릭 → 빔프로젝터에 턴테이블 화면.
2. (15분) 호수 12호 → 폭 4mm → 두께 1.8mm → 프로파일 "돔"으로 바꾸며 실시간 시연. 중량이 4.2g(18K)로 바뀌는 것을 함께 확인.
3. (30분) 학생 각자 자기 기기로 접속, 자기 호수 입력, 프로파일 5종 비교 스크린샷.
4. (25분) 스톤 추가(3mm 라운드, 프롱 4개) → 각인 "2026 KIM" → 검증 → STL 다운로드 → 슬라이서에 넣어 확인.
5. (15분) 우수작 3개를 턴테이블 영상으로 저장해 단톡방 공유.

**S2. 학생 과제 (집 → 실습실)**
- 집(아이패드): 디자인 후 "내보내기" → 기기 내 저장 + 파일 공유(에어드롭/드라이브).
- 실습실(PC): 이어서 열기(V1.5에서는 계정, MVP에서는 파일 가져오기) → 검증 재확인 → STL → 프린터.
- 제출: STL + 스크린샷 + 중량 메모를 과제함에 업로드(V1.5에서 앱 내 제출).

**S3. 브랜딩 촬영 (30분, 주 1회)**
- 완성 디자인 3개 로드 → 재질 6종으로 바꿔가며 → "9:16 · 12초 · 로고 워터마크"로 영상 3개 저장 → 릴스 업로드.

**S4. 잠재 고객 체험 (V1.5)**
- 인스타 링크 → 로그인 없이 체험 모드 → 반지 1개 → 이미지 저장(워터마크) → "실물 제작 문의" 링크.

### 2.4 사용자 여정 (MVP 기준)

| 단계 | 사용자 행동 | 화면 | 예상 소요 | 실패 지점 / 대응 |
|---|---|---|---|---|
| 진입 | 링크 클릭 | 홈(내 디자인/템플릿) | 5초 | 첫 로드 15초 초과 → 로딩 게이지 + 경량 모드 |
| 기본형 | 호수·폭·두께·프로파일 | 에디터 좌측 패널 | 2분 | 호수 모름 → "자로 재기" 안내 카드 |
| 세팅 | 스톤 선택·배치 | 뷰포트 직접 조작 | 2분 | 프롱 겹침 → 빨간 경고 + 자동 간격 제안 |

| 확인 | 재질·조명 변경 | 우측 패널 | 1분 | 프레임 저하 → 저해상도 프리뷰 토글 |
| 출력 | 검증 → 중량 → STL | 출력 패널 | 1분 | 검증 실패 → 문제 위치 마커 + "자동 수선" |
| 공유 | 턴테이블 영상 저장 | 촬영 시트 | 1분 | iOS 저장 실패 → 파일 앱 공유로 대체 |

### 3.6 F-05 3D 프린팅 출력 준비 (P0)

**목적**: 디자인을 "실제로 뽑을 수 있는 파일"로 만든다. 이 앱의 실질적 차별점.

**(1) 예상 금속 중량 계산**

```
부피(cm³) = 닫힌 메쉬의 체적(mm³) ÷ 1000      ← 스톤·보석 부피 제외
중량(g)   = 부피(cm³) × 비중(g/cm³) × 주물수축보정계수
주물수축보정계수 = 1 + 수축률 (금 1.5% → 1.015, 은 2.0% → 1.02)
```

계산 예시 — KS 12호(내경 16.67mm), 폭 4.0mm, 두께 1.8mm(중앙 최대), 돔 프로파일:
- 단면 도심 반지름 ≈ 8.33 + 0.9 = 9.23mm → 도심 원주 ≈ 58.0mm
- 단면적(프로토타입 실측): **돔 5.99mm² / 평면 7.17mm² / 각진(베벨) 6.36mm²**
- 체적 ≈ 58.0 × 5.99 ≈ 347mm³ = 0.347cm³ (돔 기준)
- **18K 옐로우골드: 0.347 × 15.5 × 1.015 ≈ 5.4g** / 925 실버 ≈ 3.6g / Pt950 ≈ 7.0g
- 화면에는 18K · 925 · Pt950 **3종 동시 표시** + 재질별 상세

> ⚠️ **초안(v0.1) 계산 정정**: 초안은 "돔 단면적 ≈ 0.65 × 폭 × 두께 = 4.7mm²"로 잡아 18K 4.2g이라고 적었는데, 이는 단면을 초승달 모양으로 본 값입니다. 반지 단면은 금속이 꽉 찬 사각형(돔은 바깥만 볼록)이므로 실제 단면적은 6~7mm²이고, 같은 치수의 18K 반지는 **약 5.4g**입니다. 초안 수치를 그대로 쓰면 주물 발주 때 금이 20% 이상 남거나 부족해집니다.
> 프로토타입은 화면의 메쉬 체적을 직접 적분해 중량을 계산하며, 파푸스 정리(체적 = 2π × 단면 도심 반경 × 단면적)와 **1% 이내**로 일치하는 것을 검증 스크립트로 확인했습니다.

**(2) Watertight(수밀) 검증 — 자동 수선 포함**

| 검사 항목 | 기준 | 실패 시 |
|---|---|---|
| 열린 엣지(구멍) | 0 | 자동 메우기 시도 → 실패 시 위치 마커 |
| 비manifold 엣지 | 0 | 자동 분리·병합 제안 |
| 뒤집힌 노멀 | 0 | 자동 재계산 |
| 자기 교차 | 0 | 자동 union 재생성 |
| 최소 벽 두께 | 기본 0.6mm (권장 0.8mm) | 경고 + 해당 영역 하이라이트 |
| 스톤 간섭/부유 부품 | 0 | 세팅 재배치 제안 |
| 단위·스케일 | mm, 실측 일치 | 자동 보정 |

- 검사는 `manifold-3d`(WASM)로 수행: `isManifold`, 체적, 표면적, 토폴로지 카운트.
- 결과 화면은 **통과 / 경고 / 실패 3단계**로 표시하고, 실패 시에만 내보내기를 막는다(경고는 사유 표기 후 진행 허용).
- "자동 수선" 버튼: 겹친 부품 union → 구멍 메우기 → 노멀 정리 → 두께 경고 재검사.

**(3) STL 내보내기**

| 항목 | 내용 |
|---|---|
| 포맷 | 바이너리 STL (V1.1에서 3MF 추가) |
| 정밀도 | 0.02 / 0.05 / 0.1mm (삼각형 수·파일 크기 미리 표시) |
| 축 방향 | Z-up(기본, 슬라이서 관행) / Y-up 선택 |
| 파일명 | `ring_KS12_dome_w4.0_t1.8_v1.stl` |
| 동반 저장 | `.jwdx` 디자인 파일(JSON) + 요약 이미지(PNG) |
| 속도 | iPad에서 10초 이내 생성 |

**수용 기준 (AC)**
- AC-05-1: 검증 통과 전에는 "출력 준비 완료" 배지가 뜨지 않는다.
- AC-05-2: 내보낸 STL이 Chitubox/Cura/PreForm에서 오류 없이 열린다(수동 확인 체크리스트).
- AC-05-3: 예상 중량과 실제 주물 중량 오차 ±5% 이내(3개 샘플 실측).

### 3.8 비기능 요구사항

- **성능**: 아이패드 9세대에서 뷰포트 30fps 이상(고품질 모드), 60fps(프리뷰 모드). 첫 로드 JS+WASM 합계 3MB 이하(gzip), 지오메트리 재생성 300ms 이하.
- **안정성**: 자동 저장 실패 시 경고, 탭 종료 전 이탈 방지 프롬프트.
- **접근성**: 터치 타겟 44px, 색 대비 4.5:1, 색만으로 상태를 구분하지 않음(아이콘+문구 병행).
- **개인정보**: MVP는 계정·서버 저장 없음(모든 데이터 기기 내). 분석 도구는 쿠키 없는 방식(Plausible 등) 검토.
- **호환**: iOS 16.4+ Safari, Android Chrome 최신, Windows Chrome/Edge 최신. Firefox는 P1.

### 3.10 F-06 자유 조형 / 스컬프팅 (D2 확정으로 P0 승격)

**목적**: 파라미터로 표현되지 않는 유기적 형태(손으로 깎은 느낌, 물결, 비대칭)를 브러시로 직접 만든다.

| 항목 | 내용 |
|---|---|
| 브러시 | 밀기(push) / 당기기(pull) / 스무스(smooth) |
| 반경 | 0.6~6.0mm (기본 2.2mm) |
| 강도 | 5~100% (기본 50%) |
| 대상 | 밴드 메쉬 정점(6~12천 개). 정점 법선 방향 변위 + 이웃 정점 평균화 |
| 입력 | 아이패드 손가락 / 마우스 드래그. 조형 중에는 오빗 회전 대신 브러시가 동작 |
| 되돌리기 | 조형 전용 스택 20단계 + "조형 초기화" |
| 검증 | 조형 후에도 위상(수밀성)이 유지되어야 하며, 출력 패널이 실제 메쉬 기준으로 재검사 |

**알려진 한계(프로토타입)**: 조형은 파라메트릭 메쉬를 "베이크"해서 편집하므로, 조형 후 호수·폭 같은 파라미터를 바꾸면 조형이 초기화됩니다(경고 표시). V1.1에서 변위 필드를 (u,v) 파라미터 좌표에 저장해 파라미터 변경에도 조형을 유지하도록 개선합니다.

**수용 기준**
- AC-06-1: 아이패드에서 브러시 이동이 16ms(60fps) 이내 반영.
- AC-06-2: 브러시 반경 안 정점만 부드러운 감쇠로 변형(경계 튐 없음).
- AC-06-3: 조형 후에도 열린 엣지 0 유지.
- AC-06-4: 조형 되돌리기 20단계.

## 5. 추천 기술 스택 및 배포 전략

### 5.1 아키텍처 개요 (클라이언트 우선)

```
[브라우저 (아이패드/PC)]
  UI(React) ── 상태(Zustand) ── 뷰포트(three.js / R3F)
        │                          │
        ├─ 지오메트리 엔진 (Web Worker) : 파라메트릭 생성·불리언(manifold-3d)·검증
        ├─ 각인 (opentype.js → Shape → 압출 → 차집합)
        ├─ 내보내기 : STL · PNG · 영상(WebCodecs/MediaRecorder)
        └─ 저장 : IndexedDB(디자인) / PWA 캐시(앱)

[서버 (MVP: 선택)]
  정적 호스팅(Vercel/Cloudflare Pages)만으로 동작.
  V1.5에서 인증·저장·공유 API 추가(Supabase 등).
```

**원칙**: 렌더링·기하 연산은 100% 브라우저. 서버는 "계정·저장·공유"가 필요해질 때만. → 서버 비용 0에 가깝게, 수업 중 네트워크 장애에도 강함.

### 5.2 기술 스택 (권장안)

| 영역 | 선택 | 이유 / 대안 |
|---|---|---|
| 언어·프레임워크 | **TypeScript + React 18 + Vite** | 생태계·AI 에이전트 유지보수 용이. Next.js는 SSR 이점이 없어 제외 |
| 3D 렌더링 | **three.js + React Three Fiber + drei** | 선언적 씬 관리, PBR 재질·환경맵·컨트롤 기본 제공 |
| 상태 관리 | **Zustand** (+ immer, zundo로 Undo) | 가볍고 모델 단순 |
| UI | **Tailwind CSS + shadcn/ui(Radix)** | 모바일/터치 대응, 커스터마이즈 쉬움 |
| 기하(불리언·검증) | **manifold-3d (WASM)** | 빠르고 견고한 메쉬 불리언, 체적/토폴로지 API 제공, 번들 ~1MB |
| 정밀 CAD(선택) | **OpenCASCADE.js** — V1.1 이후 지연 로드 | STEP/정밀 필렛용. 번들이 크고 초기화가 느려 MVP 필수 아님 |
| 각인 | **opentype.js + three ExtrudeGeometry** | 폰트 외곽선 → 형상 변환. 폰트는 OFL만 사용 |
| STL | three `STLExporter`(바이너리) + Worker | 커스텀 불필요 |
| 영상 | **WebCodecs(우선) / MediaRecorder → ffmpeg.wasm 변환** | 브라우저별 코덱 차이 대응. iOS는 MP4 필요 |
| 저장 | **IndexedDB (Dexie)** | MVP 계정 없이 로컬 저장 |
| PWA | `vite-plugin-pwa` | 홈 화면 설치, 오프라인 |
| 앱 패키징 | **Capacitor** (iOS/Android) | 스토어 배포 필요 시. 웹 그대로도 충분 |
| 테스트 | Vitest(단위) + Playwright(스모크) + 기하 골든 테스트 | 호수 환산·부피·watertight 회귀 방지 |
| 배포 | **Vercel 또는 Cloudflare Pages + GitHub Actions** | PR 미리보기 배포로 수업 전 확인 |
| 분석 | Plausible/Umami(쿠키 없음) | 학생 개인정보 최소화 |

### 5.3 저장소 구조 (모노레포 권장)

```
jewelry-studio/
├─ apps/web/                 # React 앱 (UI, 뷰포트, 라우팅)
```

결정(D1·D2)에 맞춰 **실제로 동작하고 빌드되는 1차 버전**을 제작해 공개 저장소에 올렸습니다.

### 7.2 실측 검증값 (`npm run verify`)

KS 12호 · 폭 4.0mm · 두께 1.8mm 기준, 프로토타입이 계산한 값:

| 프로파일 | 단면적 | 체적 | 18K | 925 | Pt950 |
|---|---|---|---|---|---|
| 돔 | 5.99mm² | 0.343cm³ | **5.40g** | 3.62g | 7.00g |
| 평면 | 7.17mm² | 0.416cm³ | 6.54g | 4.39g | 8.47g |
| 각진(베벨) | 6.36mm² | 0.366cm³ | 5.76g | 3.87g | 7.46g |

- 체적이 파푸스 정리와 1% 이내 일치(메쉬 416.7mm³ vs 이론 416.8mm³) — 기하 엔진이 실제 치수로 계산됨을 의미
- 세 프로파일 모두 열린 엣지 0 / 비다양체 0 (수밀)
- STL 크기 = 84 + 50 × 삼각형 (12,176 삼각형 → 608,884 bytes) 규칙 일치
- 호수 환산: KS 1호 13.000mm, KS 12호 16.667mm, KS 30호 22.667mm, KS 12호 = US 6.2호

## 부록 A. 호수 환산 공식

| 체계 | 정의 | 공식 |
|---|---|---|
| 한국(KS 신게이지, 일본 JIS S 4700 동일 체계) | 1호 = 내경 13.0mm, 1호당 +1/3mm | `내경(mm) = 13.0 + (호수 − 1) / 3` |
| 미국(US) | 1/2 사이즈 단위, 내경 기준 | `내경(mm) = 11.63 + 0.8128 × US` |
| 유럽(EU/ISO 8653) | 반지 **안쪽 둘레** mm | `EU = 내경 × π` |

예: 12호 → 내경 16.67mm → 안둘레 52.4mm → US 약 6.
참고: 국내 업체 표의 "손가락 둘레"는 반지 안둘레보다 3mm 정도 크게 적는 관행이 있어 혼동이 잦습니다. **앱은 내경(mm)을 기준값으로 저장**하고, 호수는 표시용으로만 씁니다.
> 출처: KS 신게이지 기준 공개 사이즈표(1호=내경 13.0mm, 1/3mm 간격), ISO 8653(안둘레 기준). 실제 제조사 오차 0.5호 가능.
